Infrastructure

This page covers the lab’s server, client machines, virtualization platform, network, and storage, along with the design decisions behind them and what I would change in production.

Summary

  • Windows Server 2025 VM running AD DS, DNS, and file services.
  • External DNS queries forward to Cloudflare first, with Quad9 configured as the fallback.
  • Two domain-joined Windows 11 client VMs in VMware Workstation Pro.
  • Single forest and single domain ad.comics.internal.
  • Dedicated virtual disk for the DoomVault shares.

Server Role Responsibilities

AD DS

Hosts the single forest and domain, the OU structure, and the ten fictional accounts.

DNS

Provides internal name resolution for domain authentication, service location, and endpoint registration. External queries forward to Cloudflare (1.1.1.1) first, then Quad9 (9.9.9.9) as fallback.

File server

Hosts the DoomVault share from the dedicated E: disk. The file-service controls are documented separately on the File Server page.

The domain controller and file server share one server because of local hardware limits. This is for the lab only, not a production design.

Design Decisions

Two roles on one server

Hardware limits require the domain controller and file server to share one server. This is a lab decision, not a pattern to copy.

Dedicated disk for shares

I created a separate virtual disk E: specifically for the file server role, keeping shares apart from C:.

Production Considerations

This lab is not a production design. Outside a lab, these are the changes I would make.

What I would change

  • At least two domain controllers for redundancy.
  • A separate file server.
  • DNS available on more than one server.
  • Scheduled backups with tested restores.
  • A defined patching process.

Not yet addressed in the lab

  • Backup and recovery.
  • Patch management.
  • Password and lockout policy.
  • Auditing and logging.
