File Server

This page covers the DoomVault file share, its folder structure, and how SMB, NTFS, security groups, and Access-Based Enumeration control access.

Summary

  • DoomVault file share hosted on a dedicated virtual disk (E:) separate from the system disk.
  • NTFS permissions enforce folder-level access through security group membership.
  • SMB encryption in transit and Access-Based Enumeration (ABE) are enabled.
  • Effective access validation is in progress.

Implementation Details

SMB connectivity

Users connect to the DoomVault share over SMB. The share permission includes Everyone, allowing the connection attempt to proceed.

NTFS enforcement

NTFS permissions tied to security group membership determine actual access to folders and files.

Visibility control

Access-Based Enumeration hides folders for which a user lacks access rights, reducing visible attack surface and navigation noise.

Validation status

Security group membership completion and effective access validation are in progress.

Security Notes

Current share-level permission includes Everyone. Effective security is enforced through NTFS controls and security group membership, which work together to constrain network access.

Design Decisions

Dedicated disk for shares

A separate virtual disk (E:) was created specifically for the file server role to store shares, keeping them apart from the system disk (C:).

NTFS for folder-level access

Access is hardened at the folder level through NTFS permissions and security groups rather than generic share-level controls.

Access-Based Enumeration

ABE hides folders users cannot access, reducing visible attack surface and navigation noise.

Production Considerations

This lab is not a production design. Outside a lab, these are the changes I would make.
